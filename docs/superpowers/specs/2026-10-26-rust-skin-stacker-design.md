# Rust Skin Stacker — дизайн

Дата: 2026-10-26
Статус: на согласовании

## Зачем

Steam складывает одинаковые скины Rust в одну запись инвентаря, например «8 Outlaw Revolver». Чтобы продавать или обменивать скины поштучно, стопку нужно разделить, а иногда, наоборот, собрать обратно. Надёжного готового инструмента для этого нет:
- найденные скрипты умеют только собирать;
- ArchiSteamFarm требует логин, пароль и данные 2FA;
- сайты и расширения просят доступ к аккаунту.

Rust Skin Stacker — открытое приложение для Windows и Linux. Оно делит и собирает стопки, перед запуском показывает, что изменится, а после операции сверяет количество каждого предмета. Код открыт под GPL-3.0, сборки делаются в GitHub Actions и снабжены подтверждением происхождения.

Описание продукта, пользователей и принципов лежит в `PRODUCT.md`.

## Что входит и что нет

Входит:
- вход по временному токену Steam, который хранится только в памяти;
- чтение инвентаря Rust (appid 252490, contextid 2), в том числе на тысячи предметов;
- операции: разделить всё, собрать всё, разделить или собрать выбранное, отделить N штук из стопки;
- предпросмотр операции, её ход с кнопкой «Остановить», сверка количества после;
- интерфейс на английском и русском;
- установщики для Windows (`.exe`, `.msi`) и Linux (`.AppImage`, `.deb`, `.rpm`) из GitHub Actions.

Не входит, осознанно:
- другие игры;
- продажа, трейды, цены;
- хранение токена на диске, вход по логину и паролю или по QR;
- автообновление, телеметрия;
- macOS: Tauri её поддерживает, но проверить сборку не на чем.

## Проверенные факты о Steam

| Что | Как | Статус |
|---|---|---|
| Токен | `GET https://steamcommunity.com/pointssummary/ajaxgetasyncconfig` в браузере, где выполнен вход в Steam. Поле `webapi_token` — это JWT. Заголовок кодируется как `eyAi…`, а не `eyJ`. В payload есть `sub` (SteamID) и `exp`. Можно вставить и cookie `steamLoginSecure` вида `steamid%7C%7Cjwt` | Проверено (Rust Trader, `rust_trader/steam/auth.py`) |
| Чтение инвентаря | `GET IEconService/GetInventoryItemsWithDescriptions/v1/` с `access_token`, `steamid`, `appid=252490`, `contextid=2`, `get_descriptions=true`, `language`, `count`. Страницы идут через `start_assetid`/`last_assetid`/`more_items` | Проверено с токеном (Rust Trader, `rust_trader/steam/inventory.py`) |
| Разделение | `POST IInventoryService/SplitItemStack/v1/` с `access_token`, `appid`, `itemid`, `quantity=1`, `steamid` | Проверено на аккаунте владельца: 49 из 49 |
| Сборка | `POST IInventoryService/CombineItemStacks/v1/` с `access_token`, `appid`, `fromitemid`, `destitemid`, `quantity`, `steamid` | **На аккаунте не проверено.** Тем же токеном метод вызывает открытый userscript `Kostya12rus/steam_inventory_stack`. Если в запросе `fromitemid` и `destitemid` совпадают, по отчёту на форуме разработчиков предметы пропадают |
| Поля предмета | В `assets`: `assetid`, `classid`, `instanceid`, `amount`. В `descriptions`: `market_hash_name`, `name`, `icon_url`, `tradable`, `marketable`, `market_tradable_restriction`, `tags`. Тег `steamcat` задаёт категорию (Weapon, Armor, Clothing, Misc), тег `itemclass` — тип предмета (AK47u, Large Wooden Box…) | Проверено на публичном инвентаре владельца |

Из публичного инвентаря владельца известно, что многие предметы (дропы Twitch) не передаются и не продаются: `tradable = 0`. Поэтому окно показывает, можно ли продать или обменять предмет.

## Устройство

```
src-tauri/src/
  main.rs       — запуск Tauri, регистрация команд, политика безопасности окна
  token.rs      — находит токен во вставленном тексте (JSON страницы, сам JWT или cookie), проверяет формат, срок и SteamID; значение не выводится в Debug и журнал
  steam.rs      — HTTP к Steam (reqwest + rustls): страницы инвентаря, SplitItemStack, CombineItemStacks; повторы и разбор ошибок
  inventory.rs  — ответ Steam → записи и группы предметов Rust; нечитаемые записи помечаются и не теряются
  plan.rs       — чистые функции: инвентарь + выбор пользователя → список шагов; без сети
  runner.rs     — выполняет шаги по одному с паузой, шлёт события прогресса, останавливается по правилам, в конце сверяет
  commands.rs   — команды для окна: set_token, forget_token, load_inventory, preview, start, stop, settings
  settings.rs   — язык, пауза между запросами и масштаб интерфейса, в папке настроек системы
src/
  main.ts, ui/*.ts      — окно без фреймворка
  i18n/en.json, ru.json — тексты
  assets/               — шрифт Manrope и значки Tabler, локально, без CDN
```

Логику разделения, чтения инвентаря и проверки токена переносим из Rust Trader (`E:/project/rust-trader`) вместе с выученными там уроками:
- нечитаемые записи не теряются;
- зацикленный курсор страниц останавливается;
- POST-запрос не повторяется после сетевого сбоя;
- токен никогда не попадает в текст ошибок.

Тестовые данные обезличены: в открытом репозитории не будет реальных SteamID и ID предметов.

## Окно

Утверждённые макеты лежат в `docs/design/`:
- `main-window-item.png` — выбран скин;
- `main-window-plan.png` — нажата кнопка «Разделить всё».

На макетах настоящие названия и картинки, количества придуманы.

**Каркас** — три колонки под верхней панелью:
- **Верхняя панель:** название, крупные кнопки «Разделить всё» и «Собрать всё», аккаунт и время жизни токена («7656…4821 · токен ещё 18 ч»), переключатель языка, меню с пунктами «Забыть токен» и «Настройки».
- **Слева, фильтры:**
  - поиск;
  - «Показать»: Все, Стопки, Можно собрать (у предмета есть хотя бы две записи с одинаковыми classid и instanceid — то же правило, что у действия «Собрать»), с числом предметов у каждого пункта;
  - под вариантами флажок «Нельзя передать» с числом таких предметов. По умолчанию скрыты предметы, которые нельзя передать и с которыми нечего делать: дропы Twitch и подобные (все записи непередаваемые и без даты `cache_expiration`, стопки и пары нет). Флажок показывает их и виден, только если они есть. Временно непередаваемые (дата есть) остаются в сетке, предмет без описания Steam (торговый статус неизвестен) тоже;
  - «Тип» по тегу `steamcat`;
  - внизу итог: всего штук, записей в Steam, стопок и, если есть скрытые предметы, «Нельзя передать». Итог считает весь инвентарь, как Steam, скрытое тоже.
- **В центре, сетка карточек.**
  - На карточке название, число штук, картинка и раскладка плашками: `×5`, `×4`, `3 по одному`. Каждое число подписано один раз.
  - Сортировка: «Больше всего штук» или «По названию».
  - Сетка виртуализирована и не тормозит на 5000 записей.
- **Справа, панель.** Её содержимое зависит от состояния:
  - **Ничего не выбрано** — короткая подсказка, как выбрать предметы, и что сделают массовые кнопки.
  - **Выбран один скин** — большая картинка, название, раскладка, «Можно продать на площадке Steam» и «Можно обменять» (да/нет; если доступно позже, то с датой), число записей. Дальше блок «Отделить по одному»: ползунок от 1 до `A−1`, кнопки − и +, поле числа и строка «Станет: стопка ×6 и 2 по одному · 2 запроса, ~3 с». Внизу кнопки «Отделить N» и «Собрать».
  - **Выбрано несколько (Ctrl+клик, Shift+клик)** — миниатюры выбранного, «Выбрано: 2 предмета, 20 шт.», кнопки «Разделить выбранные» и «Собрать выбранные».
  - **План операции** появляется после нажатия любой кнопки действия. Он содержит:
    - заголовок операции;
    - «Стопок затронет», «Запросов к Steam», «Займёт примерно»;
    - очередь из первых пяти стопок с миниатюрами и «и ещё N»;
    - обещание сверки;
    - кнопки «Запустить» и «Отмена».

    В сетке у затронутых карточек подписано «станет 12 по одному», незатронутые приглушены.
  - **Ход операции** — полоса прогресса, текущий предмет, «выполнено N из M, ошибок K», оставшееся время, кнопка «Остановить». Окно не блокируется: сетку можно листать.
  - **Итог** — «Готово: 72 запроса, ошибок 0» и сверка «было 121 шт. — стало 121 шт.» зелёным. Если не сошлось, красным выводится список предметов с разницей. Кнопка «Перечитать инвентарь».

**Первый запуск и вход** — отдельный экран в том же стиле:
- три шага с кнопкой «Открыть страницу токена»: страница открывается в системном браузере;
- поле вставки, куда можно вставить всю страницу целиком;
- проверка на лету: «Токен аккаунта 7656…4821, действует ещё 18 ч» или понятная ошибка;
- абзац «Почему это безопасно»: токен живёт только в памяти, запросы уходят только в Steam, код открыт.

**Прочие состояния:**
- **Загрузка** — скелет сетки, без вращающегося значка посреди экрана. В правой панели — «Загружаю инвентарь…», после каждой страницы «Записей прочитано: N из M» с полосой (если Steam не назвал, сколько записей всего, — только «Записей прочитано: N», без полосы), отсчёт, если Steam попросил подождать, и «Остановить».
- **«Стопок нет»** — «Всё уже лежит по одному». Сетка остаётся, кнопка «Разделить всё» сообщает, что делать нечего.
- **«Только непередаваемые»** — если в инвентаре одни скрытые предметы, сетка говорит об этом и предлагает кнопку «Показать их». Если поиск или тип нашли только скрытые предметы — «Нашлось только среди непередаваемых предметов, а они скрыты.» и та же кнопка.
- **Токен истёк** — плашка над сеткой «Токен истёк — вставьте новый» и кнопка, которая возвращает на экран входа. Операция в этот момент останавливается.
- **Сеть или 429 от Steam** — понятный текст и автоматическая пауза с отсчётом.
- **Настройки** — боковая панель: язык, масштаб интерфейса («Авто» по умолчанию или 100, 110, 125, 150%; зум всего окна, в маленьком окне масштаб сам уменьшается, чтобы всё поместилось) и пауза между запросами от 0,5 до 10 с (по умолчанию 1,5 с). «Авто» берёт масштаб по высоте экрана в логических пикселях: от 1400 px — 125%, от 1150 px — 110%, иначе 100%. «Авто» следит и за переносом окна на другой экран. Ctrl+= и Ctrl+− меняют масштаб (от «Авто» — от его значения сейчас; на краю списка «Авто» остаётся) и сразу его сохраняют, Ctrl+0 возвращает «Авто». Если масштаб не сменился, над сеткой плашка ошибки с кнопкой «Закрыть»; она уходит сама, когда масштаб сменится или сохранится.

**Визуальный язык:**
- Тёмная тема: фон `#0f1117`, панели `#161922`, карточки `#1b1f2b`.
- Один акцент `#5b5bf7` — на основном действии, выбранном и прогрессе.
- Успех и сверка показаны зелёным `#3ecf8e`, ошибки — красным. Без неона, свечения и градиентного текста.
- Шрифт Manrope (OFL) и значки Tabler (MIT) встроены в приложение.
- Цифры в таблицах моноширинные по ширине (`tabular-nums`). Выделение текста, фокус и полосы прокрутки оформлены в палитре.
- Анимации по 150–250 мс и только по делу: выбор карточки, появление плана, ход операции.
- Всё доступно с клавиатуры: Tab, стрелки по сетке, пробел выбирает, Enter открывает панель скина.

Интерфейс делаем по скиллу impeccable в режиме «code-led»: генерации изображений нет, поэтому эталоном служат макеты из `docs/design/`. В конце работы — finish review, затем `DESIGN.md` по построенному.

## Операции и правила

1. **Перед запуском инвентарь перечитывается.** Если он изменился с момента предпросмотра, приложение показывает новый план, а не запускает старый.
2. **Разделение.** Стопка из A штук требует `A−1` запросов `SplitItemStack` с `quantity=1`. «Отделить N» — это `min(N, A−1)` запросов. В результате получаются N отдельных предметов, остаток остаётся стопкой.
3. **Сборка.**
   - Группа — записи одного скина с одинаковыми `classid` и `instanceid`. Записи с другим `instanceid`, например с иным статусом обмена, в одну стопку не собираются. В панели скина у них стоит пометка «не соберутся» и объяснение почему.
   - Стопка назначения — самая большая запись группы, остальные переносятся в неё.
   - Перед каждым запросом проверяется, что `fromitemid` ≠ `destitemid`, что совпадают `classid` и `instanceid` и что количество взято из свежего чтения инвентаря.
4. **Повторы.** Разделение и сборка повторяются только при ответе 429, с учётом `Retry-After`, но не дольше 60 с. После сетевого сбоя запрос не повторяется: неизвестно, выполнил ли его Steam, и это покажет сверка. Чтение инвентаря повторяется при 429, 5xx и сетевых ошибках, не больше трёх раз и в общий срок 120 с на страницу вместе с запросами; ожидание по 429 окно показывает с отсчётом и при чтении. Между страницами инвентаря — пауза 1 с, её тоже обрывает «Остановить».
5. **Пауза между запросами** — 1,5 с по умолчанию, в настройках от 0,5 до 10 с.
6. **Пропуск и остановка:**
   - стопку, которую Steam окончательно отклонил (`x-eresult` не 1 или ответ 4xx, кроме 401, 403 и 429), приложение пропускает: оставшиеся шаги этой стопки (разделение — тот же `assetid`, сборка — та же стопка назначения) не отправляются и считаются ошибками, а в журнал пишется строка без ID предметов. Сетевой сбой, 5xx и непонятный ответ к пропуску не ведут: исход неизвестен;
   - три неудачи подряд: неудачные запросы или отклонённые стопки, стопка считается одной неудачей;
   - 401 или 403 («токен истёк или не подходит»);
   - кнопка «Остановить», которая срабатывает после текущего запроса. Чтение инвентаря она обрывает сразу, не дольше чем за секунду: при загрузке, перед запуском (тогда в Steam ничего не уходит и снова открывается план) и во время чтения для сверки (тогда сверки нет). Остановка самого запуска сверку не отменяет.
7. **Сверка в конце.** Инвентарь перечитывается, и для каждого скина сравнивается сумма `amount` до и после. Расхождение показывается списком и пишется в журнал.
8. **Журнал** доступен в окне через «Скопировать журнал» для отчётов об ошибках. Токена в журнале нет, это проверяется тестом.

## Токен и безопасность приложения

- Токен вставляется один раз и живёт в памяти Rust-ядра. Окно его не хранит и обратно не получает. На диск он не пишется.
- Rust-ядро ходит только на `api.steampowered.com` и `steamcommunity.com`.
- Окно в сеть не ходит. Картинки загружаются только с CDN Steam (`community.fastly.steamstatic.com`, запасной адрес — `community.akamai.steamstatic.com`), остальное запрещено политикой безопасности (CSP).
- Права окна минимальны: свои команды и события, открытие в браузере страницы токена Steam (один адрес), зум собственного окна и чтение размера окна, его масштаба и текущего экрана. Доступа к файлам и командам системы у окна нет.
- Нет телеметрии, автообновления и сторонних серверов.

## Проверка

- **Тесты Rust:**
  - разбор токена: JSON страницы, JWT, cookie, истёкший токен, чужой SteamID;
  - разбор инвентаря: страницы, нечитаемые записи, зацикленный курсор;
  - построение плана: разделить всё, собрать всё, выбранное, отделить N, граничные случаи с `A=2` и `N ≥ A`;
  - выполнение с поддельным Steam: 429, 401, сетевой сбой, пропуск отклонённой стопки (разделение и сборка), три неудачи или отклонённые стопки подряд, остановка;
  - сверка: совпало и не совпало;
  - токен не попадает в журнал и в текст ошибок.
- **Окно:**
  - проверка типов;
  - тест, что в `en.json` и `ru.json` одинаковые ключи;
  - тесты форматирования чисел и времени.
- **Ручная проверка на аккаунте владельца:**
  - сначала сборка одной пары предметов и сверка;
  - затем «Отделить N» и «Разделить всё» на нескольких стопках;
  - установка `.msi` и `.exe` на Windows, `.AppImage` и `.deb` на Linux (виртуальная машина или WSL с графикой).

## Риски

- **CombineItemStacks на аккаунте не проверен.** Первая проверка — на одной паре предметов. Если метод не работает с этим токеном, «Собрать» выходит позже отдельной версией, а разделение работает без него.
- **Steam может сам снова склеить предметы.** Повторный запуск — обычный сценарий, приложение это переживает.
- **Токен истекает примерно через сутки.** Длинная операция может прерваться: приложение останавливается, сверяет то, что успело сделать, и просит новый токен.
- **SmartScreen в Windows** предупреждает о неподписанном файле. В README объяснено, что это и как проверить файл. Платная подпись кода в первую версию не входит.
- **Linux (WebKitGTK)** может отображать окно чуть иначе, чем Windows (WebView2). Поэтому нужна ручная проверка на Linux.
- **Правила бренда.** «Steam» в названии не используем, текстуры и логотипы Facepunch не используем, пишем «не связано с Valve и Facepunch».
